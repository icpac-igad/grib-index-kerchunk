● Here's the clear answer:

  Herbie does NOT do lat/lon subsetting before download

  Both methods download the full global grid (721 x 1440 = 1 million points) for
   each GRIB message. The ICPAC region (157 x 145 = 22,765 points) is only 2.2% 
  of the global grid, and the subsetting happens after download and decode, in
  Python with ds.sel(latitude=..., longitude=...).

  This is a fundamental GRIB limitation — a single GRIB message contains one
  variable, one level, one timestep, one member as a single compressed block.
  You can't extract a spatial subset without downloading and decoding the entire
   message.

  So what IS the real advantage of GIK?

  For this specific tp-only use case, the advantages are modest:

  Column 1: Network transfer
  GIK: ~384 MB
  Herbie: ~375 MB
  ────────────────────────────────────────
  Column 1: Spatial subsetting
  GIK: After decode
  Herbie: After decode
  ────────────────────────────────────────
  Column 1: Decoder
  GIK: gribberish (Rust, ~25ms)
  Herbie: cfgrib (Python, ~2s)
  ────────────────────────────────────────
  Column 1: Decode time (51 members x 9 steps)
  GIK: ~12 sec
  Herbie: ~15 min
  ────────────────────────────────────────
  Column 1: Temp files on disk
  GIK: None
  Herbie: Writes GRIB to disk
  ────────────────────────────────────────
  Column 1: Dependency
  GIK: Pre-built parquets on GCS
  Herbie: Live ECMWF index files
  ────────────────────────────────────────
  Column 1: Offline/archival use
  GIK: Parquets work forever
  Herbie: Depends on ECMWF data availability

  The real GIK advantages are:

  1. 80x faster decoding via gribberish (Rust) vs cfgrib (Python/eccodes)
  2. No temp files — gribberish decodes from byte buffers in memory;
  Herbie/cfgrib writes GRIB to disk first
  3. Archival independence — GIK parquets capture the byte-range references
  permanently. If ECMWF removes old data from their public bucket, GIK
  references still work (as long as the S3 data exists). Herbie depends on the
  .index file being available at query time
  4. Multi-variable scaling — when streaming 12 variables (the full cGAN set),
  GIK's parallelized byte-range reads + gribberish decode massively outperforms
  Herbie's sequential cfgrib pipeline
  5. Pre-computed reference catalog — no need to parse index files at runtime;
  the parquets are ready-to-use lookup tables

  The network transfer is essentially the same because both methods do
  byte-range reads for the exact same GRIB messages. The win is in decode speed
  and operational reliability.
